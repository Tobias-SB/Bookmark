## Design rules

- **Layering (provisional, spec silent):** shared components never import from `src/features/`; the spec implies this through §5.5's feature modules but does not say it. LibraryRow is generic: it takes title, subtitle, meta text, an optional leading slot (a cover later) and optional badges; the readables feature maps a `Readable` onto it.
- **Styling:** Uniwind semantic token classes only (`bg-surface`, `text-on-surface`, `bg-primary`, `border-outline`, `text-error` and so on, from `global.css`). No raw colours, no inline style colours. Follow `TabItem.tsx` for patterns.
- **Text:** every visible string comes from a prop (callers pass `t()` strings) or from the component's own `t()` key. No literal JSX text.
- **Icons:** components take an icon as a `ReactNode` slot (IconButton, Banner, Chip, EmptyState). No icon library in this wave (decision D1). Anything that conveys a state (warning, error, selected) shows text or a text label as well as any icon (§14).
- **Touch targets:** at least 48 dp (`min-h-12 min-w-12`), including IconButton, Checkbox, Switch and TagChip.
- **Accessibility:** a role and accessible label on every interactive element; `aria-disabled`, `aria-selected`, `aria-checked` and `aria-expanded` where they apply; TagChip announces its three states in words. Visible focus on web using the `focus` token; confirm the focus-variant syntax in the installed Uniwind `.d.ts`. Never set `allowFontScaling={false}` or a `maxFontSizeMultiplier` below 2, and avoid fixed heights on text containers so 200% font scale doesn't clip.
- **Motion:** no animation in this wave. Collapsible and Snackbar appear and disappear without animating, which satisfies reduced motion trivially.
- **Platform:** no `Platform.OS`. Screen's keyboard behaviour uses `capabilities.platform` from `src/platform/capabilities.ts` (padding on iOS, height on Android, none on web). Safe areas come from `useSafeAreaInsets()`; never hard-code insets.
- **Snackbar:** a queue (one visible at a time, optional single action, auto-dismiss after a few seconds unless it has an action), a provider plus a `useSnackbar()` hook, rendered through `@rn-primitives/portal`, announced politely (`aria-live="polite"` / `accessibilityLiveRegion="polite"`). Show `AppError.message` only through mapped text, never raw errors.
- **ListDetailSplit:** splits at `NAV_RAIL_MIN_WIDTH` (reuse it) using `useWindowDimensions`.
- Confirm every `@rn-primitives`, Uniwind and safe-area API in the installed `.d.ts`, never from memory.

## Acceptance criteria

- Each component in the batch exists, is exported from its own file, and is used in at least one test.
- Testing Library (`@testing-library/react-native`, `*.test.tsx`) covers roles, labels, disabled state, selected or checked state, TagChip's three-state cycle, Stepper and NumberField bounds, SearchBar clear, Collapsible expanded state, Snackbar queue order, action and auto-dismiss (fake timers), and the AlertDialog, DropdownMenu and Select open, choose and close flows.
- Batch (d) only, per D2: keyboard behaviour on web for AlertDialog (focus trapped, Escape closes), DropdownMenu (arrow keys, Escape) and Select (arrow keys, Enter, Escape).
- No red flags (CLAUDE.md), no `any`, no `as` casts to silence errors; functions under about 30 lines.
- `npm run export:web` still succeeds (the components bundle on web under `require-corp`).

## Open decisions (owner)

- **D1 Icon set.** The spec names no icon library, and §4 says not to add one when the stack covers the need. This brief avoids the question by taking icons as slots. The first feature screen that needs real icons will need either an icon font from the Expo stack (for example `@expo/vector-icons`, with the font bundled for `require-corp`) or a small set of our own SVG icons (`react-native-svg`). Decide before Phase 1 screens.
- **D2 Web keyboard tests (§16).** No installed tool can drive keyboard events against the web rendering. Either add a third Jest project on the `jest-expo/web` preset with `@testing-library/react` and `@testing-library/user-event` (dev dependencies; the hub edits `package.json` and `jest.config.js`), or cover keyboard behaviour in the Playwright web suite (§16 E2E) and keep W5 to React Native Testing Library.
