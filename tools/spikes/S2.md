# Spike S2: how AO3 responds to anonymous fetches (spec §21 S2, §10.1, §10.2)

Run these from your own machine. Nothing here has been run. Total: 8 requests (1 + 1 + 1 + 5), one at a time. Do not add more and do not retry a failed one in a loop. If AO3 answers 429 or 503, stop and wait for the `Retry-After` time.

## Fill in first

- `VERSION`: `1.0.0` (from package.json).
- `SITE`: the project website URL. **Placeholder: replace `https://example.invalid` with the real site URL.**
- `GENERAL_ID`: a work rated General Audiences. Open any work whose header shows the General Audiences badge; the ID is the number after `/works/` in the address.
- `ADULT_ID`: a work rated Mature or Explicit. Find one by searching with a Mature or Explicit rating filter; the ID is the number after `/works/`.
- `RESTRICTED_ID`: a work visible only to logged-in users. In search results while logged in they show a lock icon; logged out, they redirect to a login or "only available to registered users" page.

## Commands

Save the block below as `s2.sh` (fill in the variables at the top) and run it with `bash s2.sh`. It makes the 8 requests in order, prints `status`, `Retry-After` and the final URL for each, and **stops the whole run on the first 429 or 503**, printing the `Retry-After` value. Do not re-run straight away after a stop; wait that long first.

Notes on the flags:

- `--max-redirs 1` with `-L`: follow at most one redirect, enough to see a login redirect in the final URL and no more.
- The burst is 5 requests 1 s apart. This is deliberately faster than §10.1's 2 s pacing, as a one-off the owner approved. Run it once only.
- `%header{}` needs curl 7.84 or later (check `curl --version`).

```bash
VERSION=1.0.0
SITE=https://example.invalid   # PLACEHOLDER: replace
UA="Bookmark/${VERSION} (Android; personal reading tracker; +${SITE})"
OUT=src/features/ao3/__fixtures__
GENERAL_ID=REPLACE_ME
ADULT_ID=REPLACE_ME
RESTRICTED_ID=REPLACE_ME
# Refuse to send anything until every placeholder is filled in.
case "$SITE $GENERAL_ID $ADULT_ID $RESTRICTED_ID" in
  *example.invalid*|*REPLACE_ME*) echo "STOP: fill in SITE and the three work IDs first."; exit 3 ;;
esac
mkdir -p "$OUT"

# get <name> <path-and-query>: saves $OUT/<name>.html and .headers.txt; exits the script on 429/503 or a curl failure.
get() {
  local line code retry final
  line=$(curl -sS -L --max-redirs 1 -A "$UA" -o "$OUT/$1.html" -D "$OUT/$1.headers.txt" \
    -w '%{http_code}|%header{retry-after}|%{url_effective}' "https://archiveofourown.org/works/$2") \
    || { echo "STOP: curl failed on $1"; exit 2; }
  IFS='|' read -r code retry final <<< "$line"
  echo "$1: status=$code retry_after=${retry:-none} final_url=$final"
  if [ "$code" = 429 ] || [ "$code" = 503 ]; then
    echo "STOP: AO3 asked us to slow down (status $code). Retry-After: ${retry:-not sent (wait 60 s)}. Do not retry now."
    exit 1
  fi
}

get general "${GENERAL_ID}"                          # 1. General work (the control)
sleep 3
get adult-view-adult "${ADULT_ID}?view_adult=true"   # 2. Mature/Explicit with the adult param (§10.1)
sleep 3
get restricted "${RESTRICTED_ID}?view_adult=true"    # 3. Restricted work, anonymous
sleep 5
for i in 1 2 3 4 5; do                               # 4. Burst: 5 x 1 s apart
  get "burst-$i" "${GENERAL_ID}"
  sleep 1
done
```

The `.headers.txt` files are for your report; they are git-ignored. The `.html` files are the intended fixtures.

## Go / no-go

- Go: `view_adult=true` bypasses the adult interstitial (request 2 is a real work page); the restricted work gives a response distinguishable from a normal work (login redirect, or the "only available to registered users" text); rate limiting, if it triggers, is 429 or 503 with `Retry-After`.
- If any of these differ it is not a blocker: adjust the `politeFetch` result mapping (`adult_gate`, `restricted`, `rate_limited`, `blocked`).
