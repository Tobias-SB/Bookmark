# Spike S1: expo-sqlite on an iPhone home-screen web app (spec §21 S1)

Throwaway. Route: `app/spike-s1.tsx` (opens its own scratch database `spike-s1.db`, table `spike_s1`). Delete the route once the result is recorded. Not passed until you send the numbers below.

## Hub to-do before this can be deployed

1. `public/_headers` now exists with COOP and COEP. The strict Content-Security-Policy from spec §18.2 is deliberately omitted for now so it cannot mask the S1 result. Add it later and re-run owner steps 2 and 6 once.
2. Run `npm run export:web`. The single-page export writes `dist/index.html`; `/spike-s1` is served by the single-page fallback.
3. The owner deploys from a checkout of `main`: `npx wrangler@4.156.0 deploy` (reads `wrangler.jsonc`; the first run opens a Cloudflare login) and notes the `workers.dev` URL it prints.
4. Check the headers before any iPhone step: `curl -sI https://<host>/` and `curl -sI https://<host>/spike-s1` must both show COOP `same-origin` and COEP `require-corp` (this is also spike S6).
5. Delete `app/spike-s1.tsx` and the `spike.s1.*` keys in `src/shared/i18n/en.ts` before any release build.

## Owner steps (iPhone, Safari)

1. Open `https://<host>/spike-s1` in Safari. The page shows "Rows stored: 0", a storage usage and quota, and a persist() result. Note any "Failed" text.
2. Share, Add to Home Screen. Open the new home-screen icon (not the Safari tab) for everything below.
3. Tap +1 three times. Rows stored should read 3.
4. Close the app (swipe it away in the app switcher) and reopen it. Record the row count.
5. Reboot the phone and open the home-screen app again. Record the row count.
6. Tap Write 5 MB four times, noting "Last action" after each (OK or the failure text). Record rows, usage and quota afterwards.
