# Spike S1: expo-sqlite on an iPhone home-screen web app (spec §21 S1)

Throwaway. Route: `app/spike-s1.tsx` (opens its own scratch database `spike-s1.db`, table `spike_s1`). Delete the route once the result is recorded. Not passed until you send the numbers below.

## Hub to-do before this can be deployed

1. Create `public/_headers` (not created by this branch). Intended contents, from spec §18.2:

```
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
```

   Spec §18.2 also wants a strict `Content-Security-Policy` (`img-src 'self' blob: data:`, `connect-src 'self'`). The spec does not give the full policy. For S1, deploy COOP/COEP first so a too-strict CSP cannot mask the result; add the CSP afterwards and re-run steps 2 and 6 once. A starting point (a proposal, not in the spec): `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' blob: data:; font-src 'self'; connect-src 'self'; worker-src 'self' blob:`.
2. Run `npm run export:web`. The route is exported as `dist/spike-s1.html` (served at `/spike-s1`) with its bundle under `dist/_expo/static/js/web/`.
3. Deploy `dist/` to the S6 host (Cloudflare Pages or the chosen free host), with a single-page-app fallback. Check the headers first: `curl -sI https://<host>/spike-s1` must show both COOP and COEP.
4. Send the owner the URL.

## Owner steps (iPhone, Safari)

1. Open `https://<host>/spike-s1` in Safari. The page shows "Rows stored: 0", a storage usage and quota, and a persist() result. Note any "Failed" text.
2. Share, Add to Home Screen. Open the new home-screen icon (not the Safari tab) for everything below.
3. Tap +1 three times. Rows stored should read 3.
4. Close the app (swipe it away in the app switcher) and reopen it. Record the row count.
5. Reboot the phone and open the home-screen app again. Record the row count.
6. Tap Write 5 MB four times, noting "Last action" after each (OK or the failure text). Record rows, usage and quota afterwards.
